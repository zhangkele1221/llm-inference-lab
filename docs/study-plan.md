# 两周学习计划

这份计划把十一个 notebook 拆成每天 1.5–2 小时的可执行任务。**每一步都有验收标准**，讲不出验收标准就说明没学会，不要往下走。

---

## 怎么用这份计划

**每天的固定流程：**

1. 打开当天的 notebook（Colab 里跑，见 README 第一节）。
2. 先读 markdown 说明，**猜一下代码会跑出什么结果**，再运行。
3. 跑完对照"验收标准"自测，**能脱稿讲出来才算过**。
4. 做当天的作业（每章末尾都有，不要跳）。
5. 把当天学到的、能用在面试里的说法，记到自己的笔记里。

**卡住了怎么办：**

- 代码报错 → 先看是不是忘了开 GPU 运行时。
- 数字和预期差很远 → Colab 是共享实例，绝对值会波动，**看趋势和比例关系**，不要纠结绝对值。
- 概念不懂 → 先看该章"面试话术"那节，它用最少的字概括了核心结论。

## 第一周：原理与机制

### Day 1 · 环境与基准工具（第 01 章）

任务：跑通环境，建立测量框架，认识 MiniGPT。

**验收标准**：能回答——

- 为什么 GPU 计时必须调 `torch.cuda.synchronize()`？
- 为什么必须先 warmup？
- `generate_naive` 和 `generate_cached` 的输出为什么必须逐位相同？

### Day 2 · Prefill vs Decode（第 02 章）

任务：推导算术强度，实测两个阶段的瓶颈。

**验收标准**：能当场做这道题——

> Llama-3-8B 在 T4（320 GB/s）上，batch=1 时 decode 的理论上限是多少 token/s？

答：320e9 / (8.03e9 × 2) ≈ 20 token/s。**并且能解释为什么实际会更慢**（kernel 启动开销、KV 读取）。

### Day 3 · KV Cache 与显存容量（第 03 章）

任务：推导 KV 公式，实测验证，做出容量计算器。

**验收标准**：能当场算出——

> 80G 卡跑 Llama-3-8B，8K 上下文，最大并发多少？

答：约 55。**关键是要能说出公式里用的是 KV head 数不是 attention head 数**，并且知道要补一句"实际要按 70-80% 打折"。

### Day 4–5 · vLLM 的调度循环（第 04 章）

任务：跑通 `EngineCore.step()` 三段式主循环，理解 `Scheduler` 与 `ModelRunner` 的职责边界。

这是整套架构的地基，建议分两天：第一天跑通并读懂追踪输出，第二天做作业。

**验收标准**：

- 能白板画出 `EngineCore.step()` → `schedule()` → `execute_model()` → `update_from_output()`，并说出每一步的输入输出。
- 能解释为什么要拆成三个模块（变更隔离），并拿"只重写一个 `schedule()` 就做出 static batching 对照组"当例子。
- 能说出 continuous batching 的收益**取决于输出长度的方差**——方差小的时候几乎没差别。
- 能说出它的代价：延迟不可预测、KV 管理复杂（正好引向第 05 章）、调度本身有开销。

### Day 6–7 · PagedAttention 与前缀缓存（第 05 章）

任务：实现 `KVCacheBlock` / `BlockPool` / `KVCacheManager` 三级结构，验证前缀复用正确性，摸清命中规律。

**验收标准**：

- 能说出 KV 层三个类各自负责什么，以及它和 `Scheduler` 的边界在哪。
- 能解释**前缀缓存命中在代码上到底是什么动作**：推进 `num_computed_tokens` + block 引用计数加一，零拷贝。
- 能写出链式哈希的公式，并解释**为什么必须链式**（防止相同内容在不同位置被误判可复用）。
- 能举出三种导致 prefix cache 完全失效的场景，第一个必须是"变量放在 prompt 最前面"。
- 能说出 block size 的权衡方向。

## 第二周：优化与实战

### Day 8 · Chunked Prefill（第 06 章）

任务：把 `max_num_batched_tokens` 从 4096 调到 256，观察长 prompt 如何**自动**被切块。

**验收标准**：能说出这两句话——

> chunked prefill 不是优化，是延迟在请求之间的**重新分配**：用长请求自己的 TTFT，换整体的尾延迟。

> 它也不需要任何新机制——只是 `Scheduler` 的 token 预算调小了，`num_computed_tokens` 自动记录进度。

第二句才是这一章真正的收获：**能看出"一个特性"其实是"一个字段的自然结果"，说明你读懂了设计。**

### Day 9 · 投机解码（第 07 章）

任务：实现投机解码，扫出负收益区域。

**验收标准**：

- 能写出收益公式 `E[tokens] = (1-α^(γ+1))/(1-α)`，成本 `γ·c_d + 1`。
- 能说出**投机解码和 continuous batching 抢的是同一份闲置算力**——并发打满时它是负收益。

### Day 10 · 量化（第 08 章）

任务：手写量化算子，测精度代价。

**验收标准**：能答出 KV cache 量化比权重量化敏感的**三个原因**：改变注意力分配结构、误差随时间累积、各层分布差异大。

### Day 11 · vLLM 实战（第 09 章）

任务：真实部署、压测、跑 prompt 结构 A/B 实验。

**验收标准**：

- 能背出六步排查法（分阶段 → 看排队 → 看 KV → 看缓存 → 调参数 → 确认输入分布）。
- **把自己线上的一段 prompt 拿出来做一次字段位置审计**，记录哪些字段会导致缓存失效。这一条是本次学习最有直接商业价值的产出。

### Day 12–14 · 毕业项目（第 10 章）

任务：搭多副本前缀路由，对比四种策略，扫描 threshold 参数。

这两天建议多花点时间，因为它直接产出你简历上的项目。

**验收标准**：

- 能讲清核心权衡：**命中率要求固定落点，负载均衡要求打散落点**。
- 产出一张"命中率 vs 负载标准差"的曲线，找到拐点。
- 写出项目总结，包含：方案、数字、代价、适用边界。

### Day 15 · vLLM 源码导读（第 11 章）

任务：在你自己的环境里定位源码、打印关键函数签名，按三轮路线读一遍。

**验收标准**：

- 能定位三个"眼"：`EngineCore.step()` / `Scheduler.schedule()` / `KVCacheManager.allocate_slots()`。
- 能指出 chunked prefill 落在哪一行（找 `max_num_batched_tokens` 和 `min(...)`）。
- 能说出 V0 → V1 重写为什么会让网上大部分源码分析失效。
- 四个动手作业至少做完一个：加日志 / 看命中数 / 改调度策略 / 提 PR。

## 学完之后

### 立刻可以做的三件事

1. **把毕业项目搬到真实环境**：把模拟副本换成真实 vLLM 实例，产出带线上口径的数字。
2. **做一次 prompt 审计**：用第 09 章的方法检查线上 prompt，估算改动能省多少成本。这是最容易落地、也最容易出成绩的优化。
3. **提一个开源 PR**：vLLM、SGLang 或 llm-d。哪怕只是文档修正，走完一次完整的开源协作流程本身就有价值。

### 和面试准备的关系

这个仓库解决的是**技术深度**问题。还要并行做两件事：

1. **简历改写**：把毕业项目写进去，数字留空等实测填。注意不要用目标值冒充成果。
2. **高频题口述练习**：每章末尾的"面试话术"就是题库，**必须脱稿讲出来**，不能只是看懂。
